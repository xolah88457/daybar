## Delivered

- Five standalone copies with Scriptable metadata headers first, no imports/dependencies. Deadline Radar remains byte-identical to its legacy original.
- Four in-scope scripts read nested `daybar-settings.json`, using exact camelCase section/key names and per-key built-in defaults. Unknown versions/fields, malformed values and invalid cross-field combinations throw rather than being reset. Relevant colors, opacity/grid tokens, tasks, titles/dates, timer options/block length, sleep targets/plan/phase timings and alert toggles are applied.
- Daily Log, Focus and Sleep use iCloud, await evicted canonical/placeholder downloads, and migrate local files only when cloud canonical and placeholder are both absent. Local originals remain. Canonical cloud data wins over local; migration validates before writing and uses the same guarded temporary-write path.
- **Crash-window recovery guard:** All four DB boundaries (`Daily Log.js`, `Days Left.js`, `Focus Timer.js`, `Time Blindness + Sleep.js`) now detect interrupted write artifacts (`.daybar-backup-*`, `.daybar-temp-*`) for the exact canonical name when both the canonical file and its `.name.json.icloud` placeholder are absent. The script **refuses with an actionable error naming the recovery files** before local migration, before default empty return, and before `expected===null` canonical creation. A recheck before creation catches artifacts appearing after the read phase. Both regular and evicted `.icloud` recovery artifacts are recognized; directory-list failures stop initialization rather than treating recovery state as empty. Only our exact live temp filename (or its eviction placeholder) is excluded. This is still not an atomic cross-device check.
- Every data mutation reads/validates latest data, applies an operation, validates output, writes a same-folder temporary file and compares current canonical text before replacement. Original is moved to a recovery backup before installing the new file; failed replacement attempts restoration and retains the backup. Malformed/unknown files never become empty overwrite targets. Daily Log uses explicit desired task state so replaying an edit does not invert it again.
- Focus persists exact contract session records keyed by decimal start epoch: `type`, `minutes`, `creditedMinutes`, `end`, `date`, optional `task`.
- **Cross-client focus integrity (parity with core `focusDataSchema`/`normalizeFocus`):** all four inline DB focus validators now enforce the conservative contract on every read and write: active timer `end - start === minutes * 60000`; session keys are canonical nonnegative safe-integer decimal strings (no leading zeros); session `end` lies within `[key, key + minutes*60000]`; `creditedMinutes * 60000 <= end - key`; session `date` is within ±1 UTC day of `end`; day `count`/`minutes` are u32. With `sessions` present, totals derive from `baseline ?? {}` plus focus `creditedMinutes`, and the file is rejected when saved `days.minutes` exceeds the derived total (untracked history) or any derived total overflows u32 — a baseline is never guessed for `sessions:{}` with nonzero days. Stale lower summaries and valid fresh ledgers without a baseline remain valid. With `sessions` absent, a present `baseline` must match the positive-minute day totals. Because validation runs before `deriveDays` on load and before `commit` on write, malformed focus files throw and are preserved byte-for-byte instead of being silently rewritten. Legacy `days` are captured once as baseline on upgrade; existing session-derived totals never create another baseline. Days derive from baseline plus sessions; block counts use floor(total / blockMinutes). Settlement is replay-safe, finished credit uses end date, early stops use stop date/whole capped minutes, breaks credit zero. Stale start/stop menus cannot replace/stop a different active session.
- Optional task picker and per-task tagged-minute thresholds write completion into the configured Daily Log using a separate re-read operation; later settlement repairs interrupted cross-file completion without duplicate focus credit.
- All legacy Shortcut ingestion forms remain: dictionary, JSON, wake string, time-only, paired segment lists/newline strings, multi-night backfill and old-bed skip rule. Sleep log/start/restart/stop/clear actions re-read the latest file. Calendar-day previous-evening attribution is preserved through DST; phone manual date/time editing uses native pickers.
- Install/backup/local-export, Keep Downloaded, settings example, widget parameters, Shortcut creation/repointing and recovery instructions in `scriptable/README.md`.

## Limitations / integration notes

1. **No real iCloud or iPhone was accessed.** Notification permissions, actual Scriptable file-manager failure semantics, iOS widget rendering/refresh and live-device sync require explicit user testing after backup. The desktop app was outside this worker's scope.
2. **No atomic replace/CAS/distributed transaction exists in Scriptable FileManager.** Same-folder temp + backup/move improves failure recovery but is not an atomic overwrite: there is a missing-canonical crash window and a race after the final comparison. iCloud's eventual consistency can still produce divergent edits/conflict copies. Session idempotence prevents replay, not writes a device has not received. Phone scripts do not delete/merge conflict copies; use the desktop resolution UI. **The new crash-window guard detects retained `.daybar-backup-*`/`.daybar-temp-*` and refuses to proceed, naming the recovery files — but does not auto-restore or delete them.** Review retained recovery files after an error/crash before resuming writes. Independent manual backup is mandatory.
3. **Focus → Habits is two files.** Session is saved first; if habits fails, the session remains credited and a later Focus run repairs completion. The contract provides no completion-ack/manual-override field, so earned linked tasks are reasserted on later Focus runs after manual unchecking. The link targets `habits.logId`, not an arbitrary Daily Log widget parameter.
4. **Countdown display is a refresh-bound snapshot.** Native iOS date timers count upward after expiry and have no supported clamp. Focus instead displays a nonnegative text snapshot, requests refresh every minute/at expiry, and retains end-clock time plus scheduled notification. iOS may leave a stale positive snapshot until refresh. No claim of second-by-second/clamped live native animation is made. Countdown today's fade uses the fixed 24-hour divisor (`86400000` ms) exactly like legacy and core — restored to legacy math — so on 23h/25h DST days it can undershoot/overshoot full white late in the day, byte-for-byte the same behavior as the legacy script (verified by the golden VM parity test).
5. **Contract seam:** `sessions` and `baseline` are independently optional in the shared schema. The phone follows DATA_FORMATS: an existing `sessions` map with no baseline means zero baseline; it never reconstructs legacy totals from already-derived `days`. Keep this behavior identical in core/backend. Neither settings nor session format needed a contract change for this delivery.
6. Settings have no widget-width/side-padding token, so legacy family widths/padding remain built in. `rows` is contract-fixed to seven. `archivedTasks` is accepted metadata; only active `tasks` count. Renames/history transfer remain desktop operations, not silent phone settings migrations.
